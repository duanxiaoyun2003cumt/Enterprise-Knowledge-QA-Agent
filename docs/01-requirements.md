# 01 需求说明

## 1. 背景与目标

面向企业员工的内部知识问答 Agent（Enterprise Knowledge QA Agent）。系统使用本地
合成 FAQ/制度文档，回答员工关于报销、差旅住宿和产品单点登录的问题；必须能展示
证据、识别资料不足和制度冲突，并支持上下文追问。

本项目同时是「小影校招 AI Agent 开发考核」的实现，分阶段完成模型接入、检索工具、
Agent Loop、安全加固和系统评测。

## 2. 功能需求

### F1 本地合成知识库

- 使用 `data/documents.json` 作为唯一权威数据源。
- 至少包含 D01–D04 四份合成文档。
- D01 规定报销期限 30 日，D02 规定 15 日；两者没有适用范围和优先级，必须保留冲突。
- D03 说明差旅住宿报销材料；D04 说明产品 X 企业版支持 SAML 2.0 单点登录。
- 加载时校验根数组、必需字段、非空字符串、唯一 `doc_id` 和合法 `version_date`。

### F2 检索与原文工具

- `search_documents(query, top_k=3)`：可解释关键词检索、同义词扩展、标题/正文加权、
  确定性排序；返回 `doc_id`、`title`、`version_date`、原样 `snippet`、`score`。
- `read_document(doc_id)`：返回完整原始文档，不修改正文。
- 空检索返回 `[]`，不是工具错误。
- 非法参数、未知 ID、数据文件损坏必须有明确异常。

### F3 Agent 动作协议

模型每次只能输出一个动作：

- `search_documents(query, top_k)`
- `read_document(doc_id)`
- `ask_user(question, reason)`
- `finish(status, answer, citations, gaps)`

状态限定为 `answered`、`needs_clarification`、`insufficient_evidence`、`tool_error`、
`incomplete`。所有动作必须带简短的 `decision_note`。

### F4 模型驱动 ReAct Loop

- 每轮由真实模型基于当前问题和已累计 Observation 选择动作。
- 工具真实结果必须反馈给模型，由模型决定下一步；不得固定“检索→读取→回答”流程。
- 非法动作不得执行工具，必须有有限重试和明确终止。
- 至少具备最大执行步数和最大工具调用次数。
- 达到预算返回 `incomplete`，不得把未验证答案标记为成功。

### F5 制度冲突与证据

- 模型负责判断冲突；程序负责最低限度的安全不变量。
- 存在未解决的期限冲突时，不得输出单一确定期限为 `answered`。
- 冲突澄清应引用双方原文，并说明缺少适用范围或优先级。
- 版本日期较新或检索分数更高不能自动视为制度优先。
- 引用必须来自当前运行中读取的文档，且为原文真实子串。

### F6 上下文追问与 CLI

- `run_agent(question, history=None)` 支持可选历史。
- 历史仅用于理解指代，不是已核实证据；需要事实时必须重新检索/读取。
- CLI 支持问题、历史文件、预算参数和 Trace 保存。
- API 配置缺失时明确失败，不得静默切换 FakeLLM。

### F7 Trace 与评测

- 每次运行记录 `run_id`、模型、动作、参数、工具结果摘要、错误类型、步数、
  工具调用次数、最终状态和停止原因。
- 不得记录 API Key、Authorization Header 或完整敏感上下文。
- 提供可重复的评测集和执行入口，区分真实模型与 FakeLLM，保留人工语义审查记录。

## 3. 安全与非功能需求

- 工具白名单：只允许四种 Schema 动作；不接受任意函数名、模块、文件路径或 Shell。
- 参数在工具执行前完成类型、必需字段和范围校验。
- 工具失败、重试、格式修复和重复动作均受预算约束；格式修复与最终结果校验使用
  独立计数器，但所有模型请求仍计入全局步数上限。
- 文档内容只能作为证据，不能作为系统指令或授权。
- `.env` 不得进入 Git；Trace 不得泄露凭证。
- 测试不依赖真实 API Key；真实模型评测与离线测试分开统计。
- 仅使用单 Agent、本地 JSON、CLI；不引入向量数据库、Web UI 或多 Agent 框架。

## 4. 验收范围

- 阶段一：配置、Schema、模型客户端、冒烟测试。
- 阶段二：合成数据、检索、工具和测试。
- 阶段三：真实模型 ReAct Loop、冲突/证据校验、上下文、Trace、CLI。
- 阶段四：硬预算、动作白名单、异常分类、文档指令隔离和敏感信息保护。
- 阶段五：测评集、执行器、真实模型运行、人工审查、对抗测试、文档替换、预算对比。
- 阶段六：独立格式/最终校验预算、重复采样、独立人类评审材料与最终交付检查。

阶段五不新增生产功能；评测中发现的安全或正确性问题优先修复并补回归测试。
